# PLC IO Gateway（Go）

一个本地可运行的工业设备采集与控制网关。用**内存模拟从站**替代真实 PLC，
实现多设备并发采集、下行写控制的确认/重试/幂等，以及设备掉线时的安全降级与恢复重同步。
全部行为在异常情况下都给出**一致且可解释**的结果（明确的质量标记与可区分的失败原因）。

## 目录结构

```
cmd/demo              本地可运行的端到端演示
internal/model        领域类型：点位、值质量、设备接口、错误分类
internal/config       JSON 配置加载、默认配置、配置校验
internal/sim          内存模拟 PLC 从站（可注入延迟/坏值/掉线/瞬时故障）
internal/collector    并发采集、地址去重合并、超时/坏值隔离、新鲜度值视图
internal/control      写指令：校验、幂等去重、确认式重试、分类拒绝
internal/gateway      编排：周期采集、掉线检测、安全降级、恢复重同步
configs/              示例配置
```

## 快速开始

```bash
# 运行端到端演示（采集 → 写入 → 幂等 → 重试 → 掉线 → 恢复）
go run ./cmd/demo

# 运行全部单元测试（-v 可看到按“业务/用例”组织的中文日志）
go test ./... -v

# 并发安全验证（数据竞争检测）
go test ./... -race
```

## 点位配置方式

配置为 JSON，字段见 `configs/gateway.example.json`：

- 顶层参数
  - `readTimeout`：单设备单次采集超时（毫秒）。某台设备超过该时间即被判超时，**不影响其它设备**。
  - `maxAge`：值新鲜度窗口（毫秒）。超过该窗口未刷新的缓存值不再是有效（good）值。
  - `writeMaxAttempts`：写指令最大尝试次数（含首次）。
  - `writeRetryDelay`：写重试之间的退避间隔（毫秒）。
- `devices[]`：设备列表
  - `id`：设备唯一标识；`safeState`：安全策略（`hold` 保持最后可信值 / `zero` 安全零值语义）；
    `readDelay`/`writeDelay`：模拟从站响应延迟；`initOnline`：初始是否在线。
- `points[]`：点位列表
  - `id`：点位全局唯一标识；`device`：所属设备；`address`：设备内寄存器地址；
  - `type`：`int` / `float` / `bool`（布尔在寄存器中以 0/1 表示）；
  - `readOnly`：是否只读；`min`/`max`：写值允许范围（写入越界会被立即拒绝）。

加载方式：`config.Load(path)`；未指定或非正数的超时/重试参数取内置默认值。
`config.Default()` 提供与示例相同的两设备四点位内置配置。

## 读语义（采集）

- **多设备并发**：每台设备一个 goroutine，各自带独立超时；单点设备慢、超时或返回坏值
  不会拖垮其它设备。
- **地址去重合并**：同一轮采集内，同一设备上的相同地址只读一次，结果共享给引用该地址的
  所有点位（同一点位被重复读到会被合并）。
- **值质量三态**（绝不含糊）：
  - `good`：本轮成功采集且在新鲜窗口内的可信值；
  - `uncertain`：有“最后一次可信值”，但当前处于掉线/刚恢复未重同步/已过期状态——
    返回旧值但**明确不可当作有效值**，并保留该值的原始时间戳（新鲜度信息）；
  - `bad`：读取失败/坏值且从无成功值——调用方不得采信。
- **坏值不覆盖**：读取失败、超时、坏值都不会写入“最后可信值”缓存，因此不会把错误值
  当成正常结果返回。

## 写语义（控制）

每条写指令带调用方提供的 `Command.ID` 用于幂等识别。

- **确认式**：只有设备真正返回成功才算 `confirmed`，此时才更新值缓存，
  保证“写命令先于随后的读视图”，写后立即 `View()` 能读到新值，下一轮采集也不会回退旧值。
- **幂等**：相同 `Command.ID` 重复下发（含多个 goroutine 并发重复）只执行一次，
  设备只被写一次，重复调用拿到同一份终态。
- **重试**：超时等瞬时错误最多尝试 `writeMaxAttempts` 次（带退避），成功即确认。
- **按可区分原因拒绝**（失败 `WriteResult.Err` 可 `errors.Is` 判断）：
  | 原因 | 错误 | 是否重试 |
  | --- | --- | --- |
  | 未知点位 | `model.ErrUnknownPoint` | 否 |
  | 点位只读 | `model.ErrReadOnly` | 否 |
  | 数值越界/类型不合法 | `model.ErrOutOfRange` | 否 |
  | 设备离线 | `model.ErrDeviceOffline` | 否 |
  | 设备明确拒绝 | `model.ErrRejected` | 否 |
  | 响应超时 | `model.ErrTimeout` | 是，至多重试 |

## 掉线降级、安全回退与恢复

- **进入掉线**：采集得到明确的“设备离线”结果（或外部 `SetDeviceOnline(false)` 注入）时，
  设备进入 `offline`，其点位立即进入安全状态：
  - 有最后可信值 → `uncertain`，**保持最后可信值及其时间戳**（`hold` 语义，使用方可据此
    回退到已知安全值；`zero` 语义下使用方应主动输出安全零值）；
  - 从无成功值 → `bad`。
- **掉线期间写控制**：写指令在入口即以 `ErrDeviceOffline` 被拒绝，不会对掉线设备做无效重试。
- **恢复重同步**：设备重新可达后，以“重新采集成功”为准完成重同步；在第一次成功采集之前，
  旧缓存被判为过期（`uncertain`），**不会把掉线期间的中间状态当正常结果**；
  成功采集后新值成为 `good`。
- **并发安全**：采集、写、视图查询、掉线/恢复切换均通过锁与每设备独立 goroutine 隔离，
  `go test ./... -race` 全程无数据竞争。

## 测试覆盖（按业务组织）

测试用 `t.Run("业务/...")` 分组，`go test -v` 的日志会逐条打印“业务 → 用例 → 结果”。

- **模拟从站**（`internal/sim`）：正常读、掉线读写、坏值/未知地址、瞬时故障按次恢复、
  设备拒绝、延迟注入。
- **并发采集**（`internal/collector`）：多设备汇总、同地址去重合并、单设备超时隔离、
  坏值不覆盖最后可信值、新鲜度过期降级、掉线保留旧值与恢复重同步。
- **写重试与幂等**（`internal/control`）：一次确认、瞬时故障重试后成功、持续超时按上限拒绝、
  相同 ID 串行/并发重复只写一次、五类拒绝原因可区分、写后读一致。
- **掉线恢复与并发读写**（`internal/gateway`）：端到端掉线安全状态、掉线写拒绝、
  恢复后重新同步为设备新值、坏值不污染、写后读自洽、多协程并发读写与掉线切换的一致性
  （`-race`）。
- **配置**（`internal/config`）：默认配置合法、JSON 加载与默认参数补齐、非法配置被拒绝。
